# 「插电弹几秒动画」可行性调研（非 root）

> 调研日期：2026-03 ｜ 目标：插入充电器 → 全屏/胶囊动画显示约 3 秒后自动消失
> 硬约束：不要 root、不要 Xposed、最多一次 adb（对最终用户 = 完全不要 adb）
> 本文结论取代《灵动岛方案调研.md》里的「充电时上岛」建议（那条是发系统通知，本文是自己画动画）

---

## 0. 结论

1. **非 root 完全可做**，有活着的先例：开源项目 RyensX/ChargingWorkshop（充电工坊，GPL-3.0，minSdk 21，Android 8+ 可用）做的就是这件事。
2. **但「插电事件」在 Android 8+ 没有免常驻的官方广播**。这是整件事唯一的死结：
   - 官方《隐式广播例外情况》白名单里**没有** ACTION_POWER_CONNECTED、ACTION_POWER_DISCONNECTED、ACTION_BATTERY_CHANGED、android.os.action.CHARGING；
   - 官方文档甚至**拿 ACTION_POWER_CONNECTED 当反面例子**：「应用以前在 manifest 里注册它，迁移到 Android 8.0 后要改成 JobScheduler 任务」。
   - 结论：**manifest 静态注册的接收器收不到插电事件**（除非 targetSdk 一直停在 25 以下，不现实）。
3. 所以只有三条路：
   - **路线 1（稳）**：前台服务常驻 + 动态注册广播 —— 行业标配，充电工坊就是这个架构；
   - **路线 2（洁癖）**：JobScheduler 充电约束任务 —— 真·零常驻，但**触发延迟不可控**，必须实测；
   - 路线 3（排除）：Xposed/root，见第 4 节参考项目真相。

## 1. 官方证据（为什么静态注册收不到）

- 《隐式广播例外情况》（Broadcast exceptions，最后更新 2026-02-26）白名单全文里只有：开机、用户、时区/闹钟、语言、USB 附件、蓝牙、电话、账号、包管理、拨号、日历提醒、存储挂载、短信 —— **没有任何电量/充电相关条目**。
- 《后台执行限制》(Android 8.0) 原文把 ACTION_POWER_CONNECTED 作为「必须改成 JobScheduler」的示例。
- ACTION_BATTERY_CHANGED 是 sticky 受保护广播，**只能动态注册**（官方 BatteryManager 文档明说）。

## 2. 展示方式：三种，观感与能力差别很大

| 方式 | 锁屏/息屏能否显示 | 关键依赖 | 评价 |
|---|---|---|---|
| **Activity**（showWhenLocked + turnScreenOn，透明/全屏主题，excludeFromRecents） | ✅ 能点亮屏幕并直接显示在锁屏上 | 需要**后台启动 Activity 的豁免** → 持有 SYSTEM_ALERT_WINDOW（官方明列的豁免项），或全屏 Intent 通知（Android 14+ 受限） | **最接近 ROM 充电动画**，推荐 |
| **悬浮窗** TYPE_APPLICATION_OVERLAY | ❌ 进不了锁屏 | SYSTEM_ALERT_WINDOW | 亮屏解锁时够用，但插电多发生在息屏时，体验打折 |
| **通知** | ✅（锁屏可读） | POST_NOTIFICATIONS（13+ 运行时） | 只能显示静态卡片，不是「动画」 |

权限代价（都是**用户在设置里手动点一次**，不需要 adb/root）：
- 必须：**显示在其他应用上层**（悬浮窗）—— 它同时是「后台启动 Activity」的官方豁免条件；
- 若走前台服务：通知权限（13+ 运行时弹窗）；
- 国产 ROM 可能还要：**自启动**、**后台弹出界面**（vivo/iQOO 确实有这一项）、电池优化白名单。

## 3. 两条落地路线

### 路线 1：前台服务常驻（稳，推荐默认）

    开机广播(豁免✅) / 首次启动 → 启动前台服务(一条通知)
      → 动态注册 ACTION_POWER_CONNECTED / ACTION_BATTERY_CHANGED
      → 插电 → startActivity(充电动画 Activity，showWhenLocked+turnScreenOn)
      → 3 秒后 finish()；拔电/满电清理

- 触发延迟：**< 1 秒**（广播本身就是实时的）。
- 代价：一条常驻通知 + 少量常驻内存；Android 14+ 必须声明 foregroundServiceType（用 specialUse，并在 manifest 里补 property android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE），否则启动即崩。
- 参考实现（充电工坊）正是如此：ChargingService 前台服务 + configBattery() 里动态 registerReceiver + ChargeActivity（excludeFromRecents、singleInstance）+ SYSTEM_ALERT_WINDOW + DISABLE_KEYGUARD + WAKE_LOCK。
- 本 App 侧优势：**已经有前台服务基础设施**（LiveService）。若用户已开启「实时刷新」，插电检测可以免费复用，不必再多一条通知。

### 路线 2：JobScheduler 充电约束（零常驻，需实测）

    开机(豁免✅)/启动时 → arm 任务 A：setRequiresCharging(true)（一次性）
    任务 A 触发 → 播动画 + arm 任务 B：setRequiresCharging(false)
    任务 B 触发（拔电）→ 重新 arm 任务 A

- 这是官方文档给的**唯一**「零常驻」迁移路径（约束控制器在电源状态变化时唤醒任务）。
- 代价与风险：
  - **延迟不可控**：可能几百毫秒，也可能被省电策略推迟到几十秒；应用处于 App Standby「受限/极少使用」桶时任务会被延后；
  - OEM 省电策略可能吞掉任务；
  - 需要两个任务做「边沿检测」，逻辑比路线 1 绕；
  - 用户「强行停止」应用后，任务会被取消且应用进入 stopped 状态，直到下次手动打开。
- 好处：**零通知、零常驻、零运行时权限**（JobScheduler 不需要任何权限，setPersisted(true) 只要 RECEIVE_BOOT_COMPLETED，属普通权限）。
- 仍需 SYSTEM_ALERT_WINDOW 才能从任务里启动 Activity（BAL 豁免）。

### 建议的产品形态

设置里给两档，默认第一档：
1. **省电模式（默认）**：JobScheduler，尽力而为，可能不弹或晚弹；
2. **增强模式**：前台服务，即时可靠，明确告知「会常驻一条通知」；
3. 共同：总开关、冷却时间（拔电后 N 秒内不重复弹）、满电不再弹。

## 4. 参考项目真相：EndfieldChargingAnim / EndfieldCharge

- 作者 NingmengLemon，**Xposed 模块**（libxposed API 102），**必须 root/LSPosed** —— 正是你排除的方案。
- 原理是**替换 ROM 自带的插拔充电动画**（hook 系统），只适配两台机型：Redmi K60/HyperOS、OnePlus 15/OxygenOS；README 明确「不发布 Release」。
- 非 root 应用**做不到「替换」**，最多「盖在系统动画上面」—— 所以插电瞬间可能先闪一下系统自带动画。
- **许可证 AGPL-3.0**：不能拷它的代码（会传染本项目），只能照视觉效果自己实现；好在本来的视觉来源 QinAnze/zmd-charge 是 MIT。
- RyensX/ChargingWorkshop 是 GPL-3.0 的**非 root** 先例，同样只能参考架构、不能拷代码。

## 5. 必须实测的未知项（1 小时）

**路线 2 的真实触发延迟**，决定能不能走「零常驻」：

1. 打一个测试 APK：arm 一个 requiresCharging 的一次性任务 + 一个 requiresCharging(false) 的拔电任务，各自打时间戳日志；
2. 用 adb shell dumpsys battery set ac 1 / dumpsys battery reset 模拟插拔（不必反复拔线），重复 10 次；
3. 记录「状态变化 → 任务执行」的毫秒差：中位 < 2s → 路线 2 成立；否则老实做路线 1（或做成两档）。
4. 顺带验证：任务里 startActivity（Activity 带 showWhenLocked + turnScreenOn）在**息屏+锁屏**状态下能否点亮并显示 —— 这是观感的成败点。

## 6. 真机实测结果（2026-10-10 ｜ iQOO V2403A / Android 16 / OriginOS 6）

测试工程：`.tools/chargelab`（最小 APK：LabActivity 布防 JobScheduler 任务 + ChargeJobService + 前台服务 WatchService 动态注册电源广播 + PopActivity 透明 Activity）。用 `dumpsys battery unplug / set ac 1 / reset` 模拟插拔，`logcat -b main -b events -v epoch` 取时间戳。

### 6.1 插电广播可信、延迟 < 1 秒

```
ACTION_POWER_DISCONNECTED  wall=1791635428158   (dumpsys battery unplug)
BATTERY_CHANGED plugged=0  wall=1791635428159
ACTION_POWER_CONNECTED     wall=1791635431336   (dumpsys battery set ac 1)
BATTERY_CHANGED plugged=1  wall=1791635431359
```

`plugged` 可区分 0=未接 / 1=AC / 2=USB，能用来判断充电器类型。**dumpsys 模拟走的是真实广播链路**，所以插电链路可以用它做自动化验证。

### 6.2 JobScheduler 充电约束：能执行，但**没法用 dumpsys 判定**（本节结论已更正）

- **正面证据**：在充电约束已被满足的状态下布防任务，`JOB_RUN` 在 **46 ms** 后就执行了（同一份 `dumpsys jobscheduler` 显示该 job 已从 `Unsatisfied: CHARGING` 变为执行）。所以「约束不响应」「任务不会跑」的说法不成立。
- **反面证据**：在「先 `dumpsys battery unplug` → 布防 → `dumpsys battery set ac 1`」的边沿场景里，等 10~20 秒任务确实不执行，约束一直显示 `Unsatisfied: CHARGING`。
- **为什么两边都不能算数**：`dumpsys battery unplug` 会把 BatteryService 置成「UPDATES STOPPED」，之后的模拟切换不再重发 `ACTION_POWER_CONNECTED`；而且模拟状态下出现过 `BatteryManager.isCharging()=false` 却 `plugged=2`（USB 供电）的自相矛盾。模拟出来的「充电」在系统内部不一致，**JobScheduler 的充电约束不能用 dumpsys 判**。
- 结论口径：**零常驻到底行不行，必须用真充电器拔插验证**；本轮数据不支持任何一方的结论。

### 6.3 后台 startActivity 在 vivo 上被静默拦截（已复现 + 权限对照失败）

- 服务活着时（`dumpsys activity services` 显示 `isForeground=true foregroundId=42`），收到 `ACTION_POWER_CONNECTED` 后调 `startActivity(PopActivity)`：**不抛异常**（`POP_LAUNCH_OK`），但 `PopActivity.onCreate` 的 `POP_SHOWN` **从未出现**，`dumpsys window windows` 里没有这个窗口，`dumpsys activity activities` 里也没有记录 —— 静默失败。
- **权限对照**：`appops set com.zmd.chargelab SYSTEM_ALERT_WINDOW allow`（官方文档所说的「后台启动 Activity 豁免」条件）之后再测，**依然不弹**。说明在 vivo 上这条官方豁免不生效，实际多半拦在 vivo 自己的「后台弹出界面」权限。（`cmd appops get` 里也确认没有 `START_ACTIVITIES_FROM_BACKGROUND` 这个 op，设置它会报 `Unknown operation string`。）
- **干扰项**：模拟插电本身会让屏幕 Asleep → Awake（系统自己的充电动画），「屏幕亮了」**不能**当成功证据；判定只看目标 Activity 自己的 `onCreate` 日志 + 窗口列表。
- 影响：想「插电弹一个全屏动画」，在 vivo 上要么引导用户额外打开「后台弹出界面」，要么放弃 Activity 改用悬浮窗 —— 但悬浮窗进不了锁屏（插电多发生在息屏状态）。

### 6.4 环境坑（本次踩到）

- 锁屏/息屏状态下 vivo 会拒绝 adb 安装；要先 `input keyevent 224` 唤醒、解锁后再装。
- 一次失败的 `install -r` 会让已装包的组件处于半残状态：之后 `am start-foreground-service` 直接报 `Error: Not found; no service started`；重装一次即修复。
- Android 14+ 测试用的前台服务必须声明 `foregroundServiceType`（本次用 `specialUse` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`，在 Android 16 上启动正常）。

### 6.5 真实充电器复测（决定性数据，覆盖 6.2 / 6.3 的结论）

场景：手机拔电 → 立刻布防任务并起前台服务 → 约 5 秒内插上**真实充电器**（非 dumpsys 模拟）。同一进程 24166 的日志（epoch 秒）：

```
ARM delay=0                              wall=1792305230399
ACTION_POWER_CONNECTED                   wall=1792305230429   (+30ms)
POP_LAUNCH_OK                            wall=1792305230450
BATTERY_CHANGED plugged=1 level=90       wall=1792305230450
JOB_RUN id=1001 charging=true plugged=1  wall=1792305230457   (广播后 28ms)
POP_SHOWN                                wall=1792305230461   (弹窗真的显示了)
POP_FINISH                               wall=1792305238465   (8s 后自动消失)
```

- **JobScheduler 充电约束可用**：真实插电后 28 ms 任务就执行，且 `charging=true`。6.2 里「不响应」的说法作废 —— 那是 dumpsys 模拟把电源状态搞坏了。
- **后台 startActivity 也能成**：App 刚被启动过、紧接着收到广播时，Activity 正常创建并显示 8 秒。6.3 里「恒定被静默拦截」要收回 —— 它是**场景相关**的：App 静置较久 / 息屏状态下的几次都静默失败，刚启动后的这次成功。

### 6.6 但真正的杀手是厂商冻结

第一次真实插电测试（布防后静置约 4.5 分钟再插）**完全失败**：`dumpsys jobscheduler` 里出现

```
frozen package name: { ... Pair{com.zmd.chargelab 10459} ... }
```

App 被系统冻住（同列表里还有微信、抖音、支付宝），**广播一条都没收到**、任务没跑，尽管系统层面 `AC powered: true`、`status: 2`、电量在涨。

→ 结论：技术链路是通的（几十毫秒级），但**能不能用取决于用户有没有把 App 加进白名单**（自启动 / 后台运行 / 电池不优化）。不做这步引导，用户会得到「有时弹有时不弹」，然后卸载。

### 6.7 修正后的触发链结论

| 方案 | 实测 | 说明 |
|---|---|---|
| 前台服务 + 动态广播 | ✅ 30 ms 内收到 | 但要防冻结；本 App 已有 LiveService 可复用 |
| JobScheduler 充电约束 | ✅ 广播后 28 ms 执行 | 零常驻可行；缺「拔电」约束，重布防要靠延迟补偿 |
| 后台 Activity 显示 | ⚠️ 场景相关 | 刚启动后可用；静置/息屏时静默失败，需要白名单或悬浮窗兜底 |

## 7. 落地实现与真机收尾（2026-10-18）

### 7.1 最终结构

- 动画：采用 **EndfieldCharge 移植版**（上游 2026-10 转为 MIT）作为唯一实现，位于 `app/src/main/java/com/zmd/charge/chargepop/upstream/`（12 个文件，含 `EndfieldHudView` / `HudTimeline` / `HudMetrics`），出处见同目录 `README-UPSTREAM.md`；自研的两版移植已删除。
- 显示：`ChargePopOverlay` 用 `TYPE_APPLICATION_OVERLAY` 悬浮窗，**能盖在桌面/任何 App 上**；进不了锁屏（Android 硬限制，已决定放弃锁屏场景）。
- 触发：`LiveService` 里动态注册 `ACTION_POWER_CONNECTED`，前台服务常驻（与「实时刷新」共用同一条通知）。
- 单位：mAh（`3465/5500`），来源是项目自己的容量表（远程表→内置表→手填→兜底）。
- 可调：设置页「岛的不透明度」30~100，另有「预览插电动画」按钮。

### 7.2 关键坑：ROM 会把第三方悬浮层按 ~0.8 合成

单层悬浮窗永远是「蒙了层灰」的半透明。像素反推（`out = a·color + (1-a)·bg`）：

- 纯黑探针 → `#333333`（0.8 压在浅色壁纸上）
- 胶囊色 `#312F30` → `#422A2C`（0.8 压在红色壁纸上）

**修复**：同内容叠 **3 层**窗口，等效不透明度 = `1-(1-0.8)^3 ≈ 0.992`，实测变回实心；用户调低不透明度时按 `1-(1-target)^(1/3)` 反算单层 alpha，滑杆手感不变。

### 7.3 锁屏结论

悬浮窗窗口在 keyguard 之下，**锁屏上不可见**；息屏插电时系统会先播自己的 FlashCharge 圆环（约 3 秒）。已加「息屏延后 3.6 秒」避让，但锁屏期间仍看不到岛 —— 该场景确认放弃（要真做只能 root/替换系统动画，或全屏通知 + 用户额外授权）。

## 8. 问题修复：应用外插电不弹岛（2026-10-19）

### 8.1 误判 bug（已修）

现象：不在应用内插电有时不弹。日志实锤：

    11:21:14.442 I ChargePop: 本应用界面在前台，跳过插电动画   ← 按 HOME 8 秒后仍误判

原因：用 ActivityLifecycleCallbacks 维护的 isUiVisible 在按 HOME 后没有及时复位（vivo 对后台 Activity 的 onStop 回调延迟）。修复：直接删除该判断 —— 插电弹岛是核心功能，任何场景（包括自己的设置页）都该弹；设置页场景的遮挡问题由「预览」按钮承担。修复后真机验证：桌面插电 → 悬浮窗岛已显示（3 层）level=100 plugged=1。

### 8.2 冻结风险（有条件缓解）

vivo 的 freezer（cached_apps_freezer=device_default，use_freezer=true）会在 App 静置后把进程放进冻结名单（dumpsys jobscheduler 里 frozen package name 可见 com.zmd.charge），冻结期间广播一条都收不到。实测发现：

- am set-standby-bucket active、appops RUN_ANY_IN_BACKGROUND allow 都解不开冻结；
- 冻结不是永久的：应用被使用过后一段时间内插电能正常弹（10:46 的成功记录）；
- 电池优化豁免（dumpsys deviceidle whitelist 有记录）不能阻止冻结。

缓解措施：设置页新增「后台保活自检」（BackgroundGuard）—— 显示电池优化豁免状态 + 待机桶（UsageStatsManager.appStandbyBucket），有风险时弹窗并跳 ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS（iQOO 上落到 BackgroundHighUsageActivity，即 vivo 的后台高耗电管理页）。冻结本身无公开 API 可检测，只能提示风险。
